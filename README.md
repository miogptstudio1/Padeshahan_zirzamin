# پادشاهان زیرزمین — نسخهٔ ۰.۳۲

پروژهٔ ربات تلگرام فارسی «پادشاهان زیرزمین» با بازی‌های گروهی، اقتصاد امپراتوری، قلمروها، جنگ بازیکنان و اتحادها، به‌همراه Telegram Mini App. برای میزبانی از **Render Web Service** استفاده شده؛ اجرای ربات به GitHub Actions وابسته نیست و GitHub فقط محل نگهداری سورس است.

## امکانات

- **فروشگاه تجهیزات:** خرید شمشیر، زره و بیش از ۱۰ نوع سلاح گرمِ صرفاً درون‌بازی با سکه‌های بازی، موجودی جداگانه برای هر بازیکن و انتخاب سلاح/زره فعال.
- **تأثیر تجهیزات بر نبرد قلمرو:** امتیاز حملهٔ سلاح و امتیاز دفاع زره در محاسبهٔ جنگ‌های بازیکنان اعمال می‌شود.
- **صندوق پاداش درون‌بازی:** هزینهٔ هر صندوق ۲۵۰ سکه است؛ پاداش می‌تواند سکه یا وسیله باشد. خرید واقعی یا پرداخت پول واقعی وجود ندارد.
- **جلوگیری از خرید/جایزهٔ تکراری:** تراکنش خرید در PostgreSQL قفل و اتمیک انجام می‌شود و شناسهٔ یکتای درخواست مانع دوباره‌پرداخت‌شدن یک درخواست صندوق می‌شود.

- بازی‌های مافیای کلاسیک و کودتا، همراه با اتاق‌های گروهی و مدیریت وضعیت بازی.
- اقتصاد امپراتوری: پاداش روزانه، کار، استخدام سرباز، خرید قلمرو و دریافت مالیات.
- جنگ قلمرو و جنگ اتحادها با دورهٔ آماده‌سازی ۱۰ دقیقه‌ای و تعیین خودکار نتیجه.
- اتحادها: ساخت و جست‌وجو، درخواست عضویت، مدیریت اعضا، انتقال رهبری، گفت‌وگوی متنی، پیمان عدم تجاوز هفت‌روزه و رتبه‌بندی.
- کمک دفاعی در جنگ اتحادها؛ هر عضو اتحاد مدافع می‌تواند در بازهٔ جنگ ۱۰ تا ۱۰۰۰ سکه خرج کند تا قدرت دفاعی همان نبرد افزایش یابد.
- فصل‌های رقابتی فصلی بر اساس UTC؛ پیروزی جنگ اتحادها ۳ امتیاز و شکست ۱ امتیاز.
- **خزانهٔ مشترک اتحاد:** اعضا می‌توانند ۱۰ تا ۱۰٬۰۰۰ سکه واریز کنند؛ فقط رهبر می‌تواند از خزانه برداشت کند. همهٔ تراکنش‌ها در PostgreSQL ثبت می‌شوند.
- **پاداش روزانهٔ اتحاد:** هر عضو اتحاد دارای دست‌کم دو عضو، هر ۲۴ ساعت یک بار ۵۰ سکه دریافت می‌کند.
- **غنیمت جنگی:** پس از پیروزی اتحاد مهاجم، ۱۰٪ قیمت قلمرو هدف (حداقل ۲۵ سکه) به خزانهٔ اتحاد مهاجم واریز می‌شود.
- **گزارش مشارکت اعضا:** نمایش کمک‌های دفاعی، واریزهای خزانه، تعداد قلمروها و تعداد سربازان اعضای اتحاد.
- Telegram Mini App با اعتبارسنجی سمت سرور `Telegram.WebApp.initData` و APIهای FastAPI.

## عضویت اجباری در کانال‌ها

برای استفاده از ربات و وب‌اپ، کاربر باید عضو هر دو کانال زیر باشد:

- [MIO GPT Studio](https://t.me/miogptstudio)
- [Shady Garden](https://t.me/shady_garden)

**ربات را در هر دو کانال ادمین کن** تا تلگرام اجازهٔ بررسی قابل‌اعتماد عضویت را بدهد. اگر دسترسی بررسی عضویت در دسترس نباشد، سیستم برای امنیت اجازهٔ ورود نمی‌دهد. عضویت هم در پیام‌ها و callbackهای ربات و هم در API وب‌اپ بررسی می‌شود.

## اجرای محلی

1. Python 3.11 را نصب کن.
2. فایل `.env.example` را به `.env` کپی کن.
3. `BOT_TOKEN` را از BotFather و `DATABASE_URL` را از یک PostgreSQL واقعی تنظیم کن.
4. وابستگی‌ها را نصب کن:

   ```bash
   pip install -r requirements.txt
   ```

5. اجرا:

   ```bash
   python run_web.py
   ```

اگر `WEB_APP_URL` تنظیم نشده باشد، اجرای محلی از long polling استفاده می‌کند. برای وب‌هوک، URL عمومی سرویس لازم است.

## استقرار روی Render

- یک PostgreSQL بساز و مقدار اتصال را در متغیر `DATABASE_URL` سرویس قرار بده.
- `BOT_TOKEN` را در Environment سرویس تنظیم کن.
- فایل `render.yaml` یک **Web Service رایگان** با فرمان `python run_web.py` تعریف می‌کند.
- در صورت نیاز `WEB_APP_URL` را روی URL عمومی سرویس بگذار؛ در Render مقدار `RENDER_EXTERNAL_URL` نیز پشتیبانی می‌شود.
- `ADMIN_IDS` و تنظیمات اختیاری را از `.env.example` بررسی کن.
- اگر توکن روی نمونهٔ دیگری فعال است، نمونهٔ قدیمی را خاموش کن تا دو ربات هم‌زمان با یک توکن اجرا نشوند.
- URL عمومی سرویس را در تنظیمات Mini App / دکمهٔ منوی ربات در BotFather تنظیم کن.

## بررسی و محدودیت‌ها

- در نسخهٔ ۰.۲۶، `python -m compileall -q .` موفق است.
- تست‌های واحد در محیط توسعه اجرا می‌شوند؛ آن‌ها اتصال زنده به Telegram، PostgreSQL یا Render را اثبات نمی‌کنند.
- پیش از استفادهٔ عمومی، اتصال واقعی PostgreSQL، دسترسی ادمین ربات به هر دو کانال، وب‌هوک، Mini App و سناریوهای چندکاربره را آزمایش کن.
- سرویس رایگان Render ممکن است بعد از بی‌فعالیتی به خواب برود و اولین پاسخ پس از بیدارشدن با تأخیر همراه شود.

## متغیرهای محیطی

نمونهٔ مقادیر در `.env.example` قرار دارد. هیچ توکن واقعی را در مخزن یا ZIP قرار نده.


## امکانات نسخهٔ ۰.۲۶
- دژ دفاعی اتحاد تا سطح ۵؛ هر سطح ۲۵ قدرت دفاعی اضافه می‌کند.
- آکادمی جنگ تا سطح ۵؛ هر سطح ۱۵ قدرت حمله اضافه می‌کند.
- سپر دفاعی ۶ ساعته با هزینهٔ ۵٬۰۰۰ سکه از خزانه؛ تا فعال بودن سپر، اتحاد هدف قابل حمله نیست.
- ارتقا و فعال‌سازی سپر فقط برای رهبر اتحاد مجاز است و هزینه‌ها در گزارش خزانه ثبت می‌شوند.
- همچنان عضویت اجباری در هر دو کانال و استقرار Render Web Service حفظ شده است.


## نسخهٔ ۰.۲۹ — رتبه‌های اتحاد و گزارش مالی

- رتبه‌های داخلی: فرمانده، خزانه‌دار، افسر و عضو عادی؛ رهبر رتبهٔ ویژه دارد.
- فقط رهبر می‌تواند رتبهٔ اعضای دیگر را تعیین یا تغییر دهد.
- خزانه‌دار و رهبر اجازهٔ برداشت از خزانه دارند؛ سایر اعضا نمی‌توانند برداشت کنند. فرمانده می‌تواند ساختمان‌های اتحاد را ارتقا دهد؛ فعال‌سازی سپر همچنان فقط برای رهبر است.
- رهبر و اعضای مجاز همچنان از سازوکارهای مربوط به نقش‌هایشان پیروی می‌کنند؛ تعیین رتبهٔ داخلی، مالکیت رهبری را منتقل نمی‌کند.
- گزارش مالی خزانه، شامل واریزها، برداشت‌ها، غنیمت جنگ، ارتقای ساختمان‌ها و فعال‌سازی سپر.
- ارتقای ساختمان و سپر همچنان فقط در اختیار رهبر است.

برای اعمال تغییرات پایگاه داده، سرویس با اجرای schema هنگام شروع، ستون رتبه را به‌صورت سازگار به جدول اعضای اتحاد اضافه می‌کند. استقرار واقعی روی Render و اتصال زنده به Telegram/PostgreSQL باید پس از آپلود و تنظیم متغیرهای محیطی بررسی شود.


## نسخهٔ ۰.۲۹ — اعلان‌های اتحاد

- صندوق اعلان‌های داخل وب‌اپ با عنوان، متن، زمان ثبت و وضعیت خوانده‌شدن.
- علامت‌گذاری یک اعلان یا همهٔ اعلان‌ها به‌عنوان خوانده‌شده.
- تنظیم روشن/خاموش برای ارسال اعلان به پیام خصوصی تلگرام.
- تنظیم جداگانهٔ دسته‌بندی‌های خزانه، رتبه‌ها، جنگ‌ها، ساختمان‌ها و رویدادهای عمومی.
- رویدادهای خزانه، ارتقای ساختمان، فعال‌شدن سپر، تغییر رتبه و اعلام/نتیجهٔ جنگ اتحادها در اعلان‌ها ثبت می‌شوند.
- اگر ارسال پیام تلگرام ممکن نباشد، اعلان داخل وب‌اپ همچنان در پایگاه داده نگهداری می‌شود.

### مسیرهای اعلان
- `GET /api/empire/alliance/notifications`
- `POST /api/empire/alliance/notifications/read`
- `GET /api/empire/alliance/notification-preferences`
- `POST /api/empire/alliance/notification-preferences`

تنظیمات PostgreSQL به‌صورت خودکار هنگام راه‌اندازی سرویس ایجاد می‌شوند؛ اجرای زنده روی Render و ارسال واقعی پیام‌ها باید پس از تنظیم متغیرهای محیطی آزمایش شود.


## نسخهٔ ۰.۲۹ — تاریخچه و رأی‌گیری اتحاد

- تاریخچهٔ رویدادهای اتحاد شامل ساخت اتحاد، پذیرش عضو، ترک اتحاد، اعلان‌های مهم و رأی‌گیری‌ها.
- رأی‌گیری داخلی با عنوان و توضیح، مدت ۱ تا ۷۲ ساعت و یک رأی برای هر عضو.
- ایجاد رأی‌گیری برای رهبر و افسر؛ حداکثر ۵ رأی‌گیری باز هم‌زمان.
- پایان خودکار رأی‌گیری در زمان انقضا؛ اکثریت سادهٔ آرا نتیجه را تعیین می‌کند و در تساوی پیشنهاد رد می‌شود.
- وب‌اپ برای ثبت پیشنهاد، رأی موافق/مخالف و مشاهدهٔ تاریخچه به‌روزرسانی شده است.

### راه‌اندازی

مثل نسخه‌های قبلی، متغیرهای `BOT_TOKEN` و `DATABASE_URL` را در Render تنظیم کن و ربات را در هر دو کانال اجباری مدیر کن: `miogptstudio` و `shady_garden`. سرویس به‌صورت Render Web Service اجرا می‌شود؛ GitHub Actions برای اجرای ربات لازم نیست.

### وضعیت تست

تست‌های واحد و بررسی نحوی در محیط توسعه اجرا می‌شوند؛ اتصال زنده به Telegram، PostgreSQL و Render باید پس از استقرار بررسی شود.

در نسخهٔ ۰.۲۹، بررسی محلی `python -m compileall -q .`، بررسی نحوی اسکریپت وب‌اپ با `node --check` و مجموعهٔ ۱۰۱ تست واحد با موفقیت اجرا شدند. این موارد جایگزین تست استقرار زنده نیستند.


## نسخهٔ ۰.۳۰ — سطح بازیکن، مأموریت‌ها و دستاوردها

- اضافه‌شدن تجربه (XP) و سطح بازیکن؛ هر ۱۰۰ تجربه یک سطح جدید ایجاد می‌کند.
- مأموریت‌های روزانه با بازنشانی بر اساس تاریخ UTC و مأموریت‌های هفتگی با بازنشانی هفتهٔ ISO.
- مأموریت‌ها بر پایهٔ آمار موجود کاربر (سربازان، قلمروها، بازی‌ها، پیروزی‌ها و سکه) بررسی می‌شوند؛ پیشرفت ساختگی یا قابل تنظیم از سمت کاربر پذیرفته نمی‌شود.
- جوایز مأموریت در هر دوره فقط یک بار قابل دریافت هستند؛ ثبت دریافت، افزایش سکه و تجربه در تراکنش پایگاه داده انجام می‌شود.
- دستاوردهای یک‌باره با جایزهٔ سکه و تجربه برای پیشرفت‌های مشخص اضافه شده‌اند.
- پنل سطح، نوار پیشرفت مأموریت‌ها و دستاوردها به Mini App اضافه شده است.
- جدول‌های جدید و ستون XP در راه‌اندازی سرویس به‌صورت سازگار ایجاد می‌شوند.

### مسیرهای جدید API
- `GET /api/progression`
- `POST /api/progression/missions/claim`
- `POST /api/progression/achievements/claim`

نسخهٔ ۰.۳۰ نیز برای Render Web Service و PostgreSQL طراحی شده است؛ عضویت اجباری در `miogptstudio` و `shady_garden` حفظ شده و GitHub Actions برای اجرای ربات لازم نیست. تست‌های محلی به‌تنهایی اتصال زنده به Telegram، PostgreSQL یا Render را اثبات نمی‌کنند.


## نسخهٔ ۰.۳۱ — تجهیزات و صندوق پاداش

- ۴ سلاح و ۴ زره با قیمت‌ها و قدرت‌های متفاوت.
- موجودی تجهیزات و سلاح/زره مجهز‌شده برای هر بازیکن در PostgreSQL.
- خرید امن با بررسی موجودی و قفل ردیف بازیکن؛ تجهیز فقط در صورت داشتن وسیله مجاز است.
- صندوق ۲۵۰ سکه‌ای با پاداش‌های سکه یا وسیله؛ شناسهٔ درخواست برای جلوگیری از پرداخت تکراری.
- عضویت اجباری در کانال‌های `miogptstudio` و `shady_garden` و استقرار Render Web Service حفظ شده‌اند.
- اتصال زنده به Telegram، PostgreSQL و Render در این محیط آزمایش نشده؛ پس از استقرار، آن را بررسی کن.


## نسخهٔ ۰.۳۲ — زرادخانهٔ گسترش‌یافته

- ۱۲ سلاح گرم درون‌بازی: تپانچهٔ نگهبان، تپانچهٔ سنگین، مسلسل دستی فشرده، مسلسل طوفان، تفنگ نگهبان، تفنگ تهاجمی، تفنگ نبرد، تفنگ ساچمه‌ای، تفنگ تک‌تیرانداز، تفنگ دوربرد، کارابین سلطنتی و تفنگ پلاسما (تخیلی).
- قیمت، ردهٔ کمیابی و امتیاز حملهٔ هر سلاح جداگانه تنظیم شده است؛ اعداد فقط برای تعادل بازی هستند و راهنمای استفادهٔ واقعی نیستند.
- سلاح‌های جدید به‌صورت خودکار در فروشگاه و فهرست صندوق پاداش نمایش داده می‌شوند و از همان سیستم خرید، موجودی و تجهیز استفاده می‌کنند.
- صندوق‌ها اکنون از فهرست آیتم‌ها بر اساس کمیابی جایزه می‌دهند، بنابراین سلاح‌های جدید نیز می‌توانند در آن‌ها ظاهر شوند.
- تست فروشگاه بررسی می‌کند که دست‌کم ۱۰ سلاح گرم در کاتالوگ وجود داشته باشد.

تمام تجهیزات با سکهٔ مجازی بازی خریداری می‌شوند؛ هیچ پرداخت واقعی لازم نیست. عضویت اجباری در کانال‌های `miogptstudio` و `shady_garden` و میزبانی Render Web Service حفظ شده است. اتصال زنده به Telegram، PostgreSQL و Render باید پس از استقرار آزمایش شود.
